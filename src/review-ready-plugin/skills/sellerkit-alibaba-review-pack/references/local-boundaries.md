# V1 Local Operation Boundaries

V1 may inspect frozen sources, fetch only public website images from the two allowlisted SellerKit hosts, build the sanitized local database, run isolated local vision features, compute exhaustive local rankings, compile local review packages, append field-review audit notes, and export local integrity receipts.

V1 does not expose Browser, Chrome, Computer Use, Alibaba network clients, Alibaba write APIs, file upload, remote draft, submit, or publish tools. Public image acquisition accepts only HTTPS URLs on `catalog.example.invalid` or `catalog.example.invalid`, sends no cookies, and writes only into the local project CAS. Unknown or prohibited tool names return `BLOCKED_REMOTE_WRITE_NOT_AVAILABLE`.

Keep these independent status axes separate:

- build: `PASS_LOCAL_REVIEW_PACKAGE_READY_NO_REMOTE_WRITE`;
- local review: `READY_FOR_LOCAL_HUMAN_REVIEW`;
- remote write: `DISABLED_NOT_REQUESTED`;
- release: `NOT_RELEASED_V1_LOCAL_ONLY`.

A local field-review record must include reviewer identity, role label, decision, rationale, UTC timestamp, exact review-subject hash, previous-event hash, and event hash. The role label is free-form and does not establish an accountability hierarchy. V1 records are `SELF_ATTESTED_UNVERIFIED` and do not automatically promote a value into `approved_internal`.

Historical commercial suggestions remain `HUMAN_CONFIRM_REQUIRED`, assets remain manual, and missing current Alibaba category Schema remains a fill-plan blocker. These are product-data constraints, not a general AI release policy.
